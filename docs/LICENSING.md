# 版权署名与 MIT 许可

本项目自有代码采用 MIT License，版权署名为：

```text
Copyright (c) 2026 yzk
```

`yzk` 是作者指定的姓名缩写。开源项目使用真名、长期使用的笔名、账号名或组织名都很常见。署名应能对应实际作者或权利人；电脑用户名和发布账号不自动决定版权归属。后续有其他作者贡献时，应按实际贡献和权利关系保留其声明。

## 普遍做法

1. 在仓库根目录放完整 `LICENSE`，包含年份、作者和许可正文。
2. 在 README、软件“关于”位置和安装器元数据中简要署名，并指向许可文件。
3. 分发源码和安装包时携带许可；对第三方库、图标、字体单独保留原始版权和许可。
4. 多人项目可采用 `项目名 contributors`，或保留各作者的既有声明。新增年份时，根据实际更新使用单个年份或年份范围。

本项目已在根目录 `LICENSE`、README、Python 项目元数据、网页“关于项目”和 Windows 安装器元数据中落实该署名。Windows ZIP、EXE 安装目录及 Linux 应用目录携带项目许可和第三方声明。

## MIT 允许与要求

MIT 允许他人使用、修改、合并、发布、再分发、商用及销售软件副本。再分发软件副本或其重要部分时，应保留版权和许可声明。MIT 不要求衍生项目必须继续开源，也不要求另行支付许可费；同时包含原文中的无担保与责任限制条款。

因此，“仅限个人研究学习”“禁止商用”“禁止再分发”等限制与这里采用的 MIT 条款不一致，项目界面已改为 MIT 声明。用户自己的模拟输入和结果不因使用本软件而自动改为 MIT。

MIT 仅覆盖作者有权许可的本项目内容，不会把 GROMACS、ACPYPE、Open Babel、CUDA 库或字体改成 MIT。它们各自的再分发、署名、源码提供等义务仍须遵守，见根目录 `THIRD_PARTY_NOTICES.md` 和原始包内许可证。字体的 OFL 文件和 Lucide 图标许可也随程序保留。

## 声明与登记

版权声明和软件著作权登记是不同的事情。通常版权随符合保护条件的作品创作而产生，放置 LICENSE 用于说明许可条件，不等于完成登记。若需要用于商业合作、学校成果证明或权属证据，可另行按所在地制度申请计算机软件著作权登记，并保留源码版本、发布记录和贡献记录。

安装包数字签名用于验证发布者和文件完整性，也与版权声明、MIT 许可及软件著作权登记分别处理。当前安装包未附代码签名证书。
