# 试用与运营验证

核心路径：下载 → 环境就绪 → 示例完成 → 自有数据任务 → 结果导出 → 再次复用。

先邀请 5–10 位有分子动力学基础的目标用户自愿试用，记录系统/硬件、安装耗时、环境失败原因、首次结果耗时、求助次数和恢复结果。完成一轮基线采集后再设转化目标。

可通过“帮助与诊断”查看本机真实任务状态数量和复制次数。教学示例与 Dry run 不计入真实任务完成数量。该数据只代表当前机器仍保留的任务，不是用户数、安装转化率或留存率。软件没有后台分析上传。

建议试用记录字段：匿名试用编号、系统类别、首次安装/已有环境、环境是否就绪、示例是否完成、自有任务是否完成、是否导出结果、失败类型、恢复是否成功、求助分钟数、30 天内是否进行第二次研究任务。以研究项目周期解释复用情况。

模板复用、参数差异、项目组织和结果交付是当前优先方向。条件矩阵批次、共享工作站、远程集群和商业服务应在访谈确认使用频率、权限需求和支持成本后分别立项。当前实现仍是本地单用户工具，不宣称具备多租户授权或远程调度能力。
