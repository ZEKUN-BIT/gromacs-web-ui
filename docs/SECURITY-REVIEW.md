## 部署与信任边界

应用面向本地单用户，在 Linux 或 Windows 的 WSL2 中运行，默认通过 `127.0.0.1`/`localhost` 访问。应用没有实现账号登录、多租户授权或网络传输加密。空间清理的预览 token 用于绑定操作意图，不是登录凭据；不能以它替代用户认证。其他已有 API 也没有因此获得统一的来源认证。

本次复核假设操作系统账号、运行目录权限和安装的计算工具由使用者控制。检查覆盖不可信文件名、畸形输入及草稿、浏览器跨来源调用，以及 Web、worker、克隆与清理之间的竞争；应用没有将 GROMACS 等第三方文件解析程序隔离成可接收任意不可信计算输入的沙箱。运行清单包含本机路径和硬件信息，按本地研究数据管理。需要远程使用时，应通过已有的 VPN、SSH 隧道或具备认证的代理提供访问控制，不能直接把当前无认证服务暴露到公网。

## 复核发现与修复

| 编号 | 类别 | 级别 | 发现 | 最终处理 |
| --- | --- | --- | --- | --- |
| SR-01 | A03 注入 | 中，限定于本地草稿恢复 | 配体卡片将草稿中的 `count`、`charge`、`ph` 直接插入 HTML 属性；畸形字符串可能生成额外 DOM。没有发现独立的远程写入草稿攻击链。 | 三项属性均使用 `escapeHtml` 转义；其他动态文本继续使用转义或 DOM 文本接口。 |
| SR-02 | A08 数据完整性 | 中 | 实验清单固定使用 `experiment-manifest.json.tmp`，可能覆盖并移走同名上传输入；上传生成文件的保留名也会与系统产物冲突。 | 清单使用随机、独占创建的临时文件并原子替换，失败清理临时文件；上传拒绝清单、元数据和运行日志保留名，清单生成函数再次拒绝同名输入，保护旧任务克隆路径。 |
| SR-03 | A05 安全配置 | 低 | 畸形 `Origin` 的解析异常可能令来源校验返回服务器错误。 | 空间管理来源校验捕获无效来源并返回 403；跨来源、错误端口及浏览器 `cross-site` 请求均拒绝。 |
| SR-04 | A08 数据完整性 | 低，仅本地导出方法 | 显式元数据导出仍通过固定 `metadata.json.tmp` 写入，可能覆盖同名文件或跟随该临时路径的符号链接。 | 导出持有共享任务文件锁，使用随机独占临时文件及原子替换，拒绝目标符号链接，失败清理临时文件。最终目标的符号链接原本会被 replace 替换，实际写穿风险来自固定临时路径。 |

本次检查没有留下未处理的严重或高危发现。完整任务删除会移除任务记录，当前功能不提供独立的、防篡改的删除审计档案；本地方法或具有相同操作系统权限的程序也不受 HTTP 来源校验约束。

## OWASP Top 10 检查结果

| 类别 | 本次结果 | 检查与证据 |
| --- | --- | --- |
| A01 访问控制失效 | 在本地部署边界内通过 | 清理请求使用严格 Pydantic 模型，仅接受任务 ID 和明确选项，拒绝任意路径、穿越和额外字段。`storage.py` 对目录逐层使用 `O_NOFOLLOW` 和目录描述符扫描、删除；符号链接及特殊文件不进入自动清理。空间 POST 校验本机同来源；跨来源与穿越 API 回归通过。应用仍无账号权限模型。 |
| A02 加密失效 | 本次未引入新的凭据或加密机制 | 上传和清单使用 SHA-256 作完整性记录；预览 token 使用 `secrets.token_urlsafe`。token 只在内存保存且短期有效。本地文件和 SQLite 沿用操作系统权限保护，没有声称提供静态数据加密或 HTTPS。 |
| A03 注入 | 发现并修复 SR-01 | SQLite 数据值、研究检索和分页均采用参数化 SQL；SQL 结构来自固定代码。外部计算使用参数数组调用 `subprocess.Popen`，没有启用 shell。新空间界面使用 `textContent`/`new Option`；其他动态 HTML 使用转义。恶意任务名称及确认框的浏览器回归通过。 |
| A04 不安全设计 | 通过 | 默认保护输入、拓扑、MDP、checkpoint、生产轨迹、分析报告和活动任务；日志需单独选择，完整删除需明确选择并再次确认。预览绑定任务、选项、运行根目录、存储修订和文件指纹，10 分钟过期且单次使用；缓存最多 16 项、每次预览最多 100000 个文件系统条目。执行阶段再次检查状态、进程身份和指纹。 |
| A05 安全配置错误 | 发现并修复 SR-03 | 检查了 CSP、`nosniff`、禁止嵌入和 referrer 策略；没有新增 XML/DTD 解析。应用保留单 Web worker 限制；预览内存状态与该限制一致。运行根目录和锁文件的符号链接检查、来源拒绝及响应头测试通过。 |
| A06 易受攻击和过时的组件 | 已核验依赖审计 | `/tmp/gromacs-dependency-audit.json` 中列出的 43 项依赖，已知漏洞为 0，跳过项为 0；报告未提供修复项。结果只覆盖报告所列版本和审计时已知漏洞，不构成整个操作系统、GROMACS 或其他外部工具的安全保证。 |
| A07 身份识别和认证失效 | 架构边界明确 | 未添加账号、口令、cookie 会话或认证 token。空间预览 token 不授予身份权限；新来源检查也不等同于全站认证。审阅结论仅适用于前述本地单用户部署。 |
| A08 软件和数据完整性失效 | 发现并修复 SR-02、SR-04，其余检查通过 | 清单完整后才入队，失败任务不可被 worker 领取；上传过程中累计的哈希仅在文件指纹匹配时复用。SQLite 是状态权威，JSON 导出可重建，迁移只执行一次，旧文件不能让已删除任务复活。文件锁及持久化 maintenance/deletion 标记阻止并发启动和复制；失败清理递增修订并可重试。JSON/Pydantic 路径未使用 pickle、eval 或动态执行。 |
| A09 安全日志和监控不足 | 本地诊断范围内通过 | 保留 `last_cleanup`、失败信息、修订以及可恢复的 pending 状态；完整删除结果返回调用端。磁盘监控即使遇到数据库写入失败也会尝试停止已验证身份的进程组；不会仅凭 PID 给复用的进程发信号。日志可由用户显式删除，当前实现不提供防篡改审计或远程告警服务。 |
| A10 服务端请求伪造 | 本次未新增相应入口 | 新功能处理本地任务 ID 和文件，不接收任意远程资源 URL，也不增加服务端按用户 URL 发起请求的逻辑。计算命令与本地诊断工具的现有信任边界保持在用户安装的工具范围内。 |
