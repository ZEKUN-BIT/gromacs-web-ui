## 0.1.1 WSL provisioning correction

The original installer discarded elevated WSL output, treated every nonzero exit code as a restart requirement, and installed a distribution in the elevated account. The user's original machine failure remains undiagnosed because that version did not record the native failure.

The elevated helper now runs only the fixed `wsl --install --no-distribution` command, with optional official web download. Ubuntu registration runs in the original Windows user context. Native stderr and HRESULT are recorded, 3010/1641 and pending Windows features are handled separately, and diagnostics do not change the system. The helper accepts a validated hexadecimal log identifier, not a command or arbitrary output path. Shared logs contain system/account details but no application credentials; the current user's log is bounded by rotation.

Dependency requirements did not change; the existing production audit remains applicable to the installed dependency snapshot. New mocked PowerShell regressions execute the actual native stderr/exit-code wrapper and cover network errors, restart codes, supported/legacy flags and elevation boundaries. They do not perform real feature installation or replace Windows hardware acceptance testing.

## 0.1.3 WSL raw command-line correction

The 0.1.2 native wrapper quoted every argument. Microsoft's [WSL client](https://github.com/microsoft/WSL/blob/master/src/windows/common/WslClient.cpp) compares the first raw token to Windows options; [ParseArgument](https://github.com/microsoft/WSL/blob/master/src/windows/common/helpers.cpp) retains quotes. Thus `"--install"` falls through to the Linux shell, matching the user's Bash error and exit 127. The same problem prevented existing distro detection.

Ordinary arguments, including WSL options, now remain unquoted. Empty strings and values containing whitespace or quotes still use Windows backslash/quote escaping. ProcessStartInfo continues to use a fixed executable with UseShellExecute disabled; shell metacharacters are not evaluated on Windows. Logs now record the actual executable and serialized arguments before launch. Elevation boundaries, fixed downloads, checksums and data preservation are unchanged; no new dependencies or remote inputs were added.

Reviewed the changed argument/input and logging paths against all ten OWASP categories: no new security findings. Dependency requirements did not change; the previous production dependency audit applies to the same installed snapshot. Tests first reproduced the faulty option serialization, then passed after the correction, including actual native argument round trips and mocked no-download reuse with an older version-reporting CLI. The eleven Python packaging tests, including local service start/reuse/HTTP/stop, pass; PowerShell regressions and syntax checks pass on Linux PowerShell 7.

Windows CI now requires a real read-only `wsl.exe --help` probe under Windows PowerShell 5.1 before provisioning mocks. Missing WSL fails that CI check; Linux explicitly skips it. This Windows check has been added but not executed in this workspace. Windows installation, WSL import/reboot and hardware acceptance remain outstanding. Review status: PASS for the scoped code change, with these runtime validation limits.
